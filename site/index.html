Three layers, like a company card

You decide what your agent may do on its own, what needs your OK, and what can never happen.

Routine

Pays on its own

Small, expected payments go through automatically, within limits enforced on-chain by your smart account.

e.g. up to 2 USDC per payment, 5 USDC a day, to your API provider
Big or unusual

Asks you first

Anything above the limits becomes a request on your phone. Approve with Face ID or fingerprint. No seed phrase, no extension.

e.g. a 4 USDC annual plan: one tap, then it's paid
Forbidden

Never happens

Addresses on your denylist and amounts above your hard maximum are refused outright, and never even offered for approval.

e.g. a vendor you don't trust, or more than 20 USDC

Try it in 10 minutes

Everything runs on the Base Sepolia testnet with free test tokens. You need a phone or laptop with a passkey (Face ID, fingerprint, Windows Hello) and, optionally, a wallet like MetaMask as recovery address.

Open the app

Go to app.cyphosguard.com and create a passkey. If you want a recovery address, enter it now: changing it later changes your account address.

Get test ETH

Copy the account address the app shows and send it 0.0001 test ETH: one claim from the Coinbase faucet is enough (free Coinbase Developer account). Alternative: ETHGlobal faucet (free login, 0.05 ETH a day). More: Base's faucet list. Test USDC (no ETH): Circle.

Create your agent's key

On the machine where your agent runs: npx @cyphos-guard/cli agent new --env agent.env. It prints the agent's address; send that a little test ETH for gas. The key never leaves your machine.

Grant and try

In the app, click Create account, then grant the agent's address a budget. Connect it to Claude with the MCP command and ask it to pay something. Above the limit, approve on your phone.

No sign-up at all

Run everything locally on a fork of Base Sepolia: no faucet, no API key. Quick start on GitHub.

See it on-chain

Paste your account address into Basescan (Base Sepolia) to see every payment. Add the network to your wallet via Chainlist.

Stuck or found a bug?

Open an issue on GitHub. Security problems: please report privately via the repo's Security tab. Guides: MCP setup · SDK · recovery page.

Built for agents that pay

Everything an agent operator needs around the payment itself.

On-chain limits

Per-payment and per-day caps, allowed recipients and contract functions, expiry. Checked by the blockchain on every payment.

Passkey approvals

Approve big payments on your phone with Face ID or fingerprint. Each approval allows exactly that one payment, once.

Non-custodial

The service never holds a key that can move your funds. You can revoke and withdraw anytime, even without the service, via your recovery address.

Pay x402 APIs

Agents can pay HTTP 402 APIs per request in USDC, within your limits, asking you above them. Tested against the official x402 facilitator.

Works with Claude

An MCP server gives Claude Code, Claude Desktop and other MCP agents tools to pay, fetch paid APIs and check approvals.

Full audit trail

Every payment, request, approval and block, with the agent's stated reason and the on-chain receipt, in one activity log.

What you don't have to trust

cyphos-guard is built on the MetaMask Delegation Framework, so the important rules live in your smart account.

Enforced on-chain

Recipients, per-day caps, contract functions, expiry, and one-shot approvals. These hold even if the cyphos-guard service is down or compromised. With the optional co-signer, per-payment caps are binding on-chain too.

Worst case, bounded

If an agent's key is stolen, the thief gets the agent's permission and nothing more: your limits, your recipients, within the budget you put in. Revoke it in one click.

No seed phrase

Your wallet is owned by a passkey on your phone, synced by iCloud Keychain or Google Password Manager. A recovery address you control is the backup.

Honest status

Working MVP on Base Sepolia testnet. Not audited. No token, no DAO, no mainnet before an independent audit.

For developers

A TypeScript SDK, an MCP server and a CLI. Your agent keeps its own key; the owner only ever sees its address.

// pay within limits, ask the owner above them
const pw = createCyphosGuard({ policyServiceUrl, agent });

await pw.execute({ to: vendor, value, reason: "GPU credits" });

// pay an x402 API per request
const { response } = await pw.payX402(
  "https://api.example/report", {},
  { reason: "weekly market report" });
# create the agent's own key (never leaves your machine)
npx @cyphos-guard/cli agent new --env agent.env

# give Claude the tools: pay, fetch_paid_api, check_approval…
claude mcp add cyphos-guard \
  -e CYPHOS_AGENT_PRIVATE_KEY=0x… \
  -e NETWORK=live \
  -e CYPHOS_POLICY_SERVICE_URL=https://app.cyphosguard.com/api \
  -- npx -y @cyphos-guard/mcp

Questions

Short answers to what people ask first.

Can my agent drain my wallet?

No. It can only spend from the account you funded, only to recipients you allowed, and only up to your limits per payment and per day. Your main wallet is never connected.

Do I need a seed phrase or a browser extension?

No. You sign with a passkey (Face ID, fingerprint or security key). Optionally, you add a recovery address from a wallet you already have.

What happens if cyphos-guard goes offline?

Your funds stay in your smart account and the on-chain limits keep holding. With the wallet you set as recovery address (e.g. MetaMask), you can stop every agent at once and move everything out on the recovery page, which works without the cyphos-guard service.

Which networks?

Base Sepolia testnet today (Ethereum Sepolia as fallback). Mainnet only after an independent security audit.

Which agents work with it?

Anything that can call the TypeScript SDK, and any MCP client such as Claude Code or Claude Desktop.
